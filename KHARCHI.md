# Kharchi: the one document

Last updated 19 Oct 2026. This file is the single source of truth for what the app is, how to run and ship it, what was decided and why, what is verified, and what is still open. If code and this file disagree, the code wins: fix this file in the same change.

"Kharchi" is a working name, defined once in `src/config/app.json`. See section 16 for the naming work.

---

## 1. What it is

One Android/iOS app (React Native, Expo SDK 57, TypeScript) that combines:

1. A **personal expense tracker**: manual entry, share-in of bank messages, voice entry, scanned bills, budgets, recurring items, goals, tags, search, CSV.
2. A **Splitwise-style group splitter**, free and unlimited: six split types, multiple payers, multi-currency, minimum-transfer debt simplification, settle up (including UPI links), comments.
3. **Insights and an on-device assistant**: charts, forecast, subscriptions, anomalies, monthly review, money health score, and tap-only questions answered from your own data.

Everything runs on the phone with a local SQLite database. There is no backend, no account, no analytics and no ads. Money is stored as integer paise, never floats.

The Play Store build is the **Privacy-First edition**: no SMS permission, no internet permission, no account. Bank messages are pasted or shared in and the user confirms them.

## 2. Run it

```bash
cd ~/Desktop/Fermor/kharchi
npx expo start
```
Then, in **Expo Go**, tap **Scan QR code** and scan the terminal's code. Do not use the phone's camera app. The terminal must say **"Using Expo Go"**.

- Why this works with plain `npx expo start`: `expo-dev-client` sits under `optionalDependencies` (still installed, native builds unaffected) and `.env` has `EXPO_NO_REDIRECT_PAGE=true`. Before that, Expo assumed a development build and the camera opened an old installed Kharchi carrying its own old screens. To undo: move `expo-dev-client` back to `dependencies` and delete that `.env` line.
- If the phone cannot reach the Mac (different network, hotspot trouble): `npm i @expo/ngrok --no-save --legacy-peer-deps && npx expo start --tunnel`.
- First launch: after the three welcome screens a **development build** (Expo Go) loads the complete demo data automatically. Store builds never do. Anywhere else: More, Developer, **Load complete demo**.
- Native features need a development build (`npm run android:dev`): bill scanning with camera or gallery, the widgets and shortcuts, SMS (Full edition only), reminders, share-into-app. In Expo Go they are feature-detected and degrade gracefully; use the sample bill and paste.
- Tests need **Node 22** (`PATH=~/.nvm/versions/node/v22.23.3/bin:$PATH npx jest`), because Node 20 has no `node:sqlite`.
- `npm run check` = typecheck + lint + tests. Never edit `android/` or `ios/`; they are generated by `npx expo prebuild`.
- Browser preview (a testing aid, not for users): `KHARCHI_PREVIEW=1 npx expo start --web --port 8101` (needs `npm i sql.js --no-save`). Shims live in `preview/` and `metro.config.js` and apply only with that flag on web.

## 3. Features (what exists)

### Tracker
- Transactions: expense, income, transfer; amount, category, merchant, note, date, account, payment method, **tags**, **receipt** (Plus), and **leave out of my totals**.
- Accounts (cash, bank, UPI, card, wallet) with balances; categories (12 expense, 6 income, plus custom); budgets (overall and per category); recurring (weekly, monthly, yearly, with catch-up); search and filters; delete with Undo; CSV export and import (including generic bank statements); full JSON backup and restore; Delete all my data.
- **Frequent expenses**: one-tap chips on the Add sheet from what you pay for repeatedly.
- **Leave out of my totals**: from the transaction screen or by long-pressing a row in Activity. The entry stays in the list as "Not counted" and is skipped by every total, budget, chart, forecast, review, health score and assistant answer. Account balances still include it because the money moved. Kept through CSV and backup.

### Capture (low friction, no sensitive permissions)
- **Share a bank message to Kharchi** (or paste): opens a review screen; the parser reads amount, direction, merchant, date, last 4 digits; dedupe by fingerprint; unsupported text creates nothing; the message text is never stored (hash only).
- **Say an expense** (More, or the button on the Add sheet): dictate with the keyboard's own microphone key, or type. A deterministic on-device parser makes one reviewable draft per amount ("spent 180 on lunch and 60 on tea" gives two). Kharchi never requests the microphone and never records. Do not call this "offline": that depends on the user's keyboard.
- **One review step** for share, paste and voice (`features/capture/DraftEditor.tsx`): large amount, editable description and category, an honest label of where the category suggestion came from (your earlier choices, your always-rule, or "guessed from the words"), Save with Undo, Discard, double-tap protection.
- **Quick add** and **Scan bill** home-screen widgets and long-press launcher shortcuts. There is **no** Quick Settings tile and no back-tap or double-tap feature (removed at the owner's request; Android has no public back-tap API).
- **Scan bill** (see section 11): snap a bill, split it item by item later.
- Optional (Full edition only): automatic bank SMS capture with inline-reply notifications.

### Groups
Equal, exact, percent, shares, adjustment and itemised splits (with proportional tax and tip, and discounts); multiple payers; multi-currency with a stored rate; exact minimum-transfer simplification (up to 16 people, greedy beyond); settle up by cash or UPI link; per-friend balances; activity feed with edit history; group charts; local reminders; share a group summary as text or image; your share lands in your personal tracker; **comments** on shared expenses. Reopening a saved expense for editing restores its saved split values.

### Insights and assistant
Category donut, daily heatmap, income versus expense, top merchants, vs last month, pace and month-end forecast, subscription detection, anomaly flags, savings tips.
- **Assistant**: tap-only. The on-device engine understands a fixed set of questions, so the screen offers grouped, tappable questions built from your own categories and months (`features/ai/catalog.ts`) and has no free text box that would promise more than it can answer. Every offered question is tested to return a real answer, also on an empty app. Nothing is sent anywhere.
- **Monthly review**: your month as one card (kept, top categories, no-spend days, biggest expense, heaviest day), browse months, share as an image (Plus).
- **Money health score** (Plus): 0 to 100 from four visible parts (savings rate, budgets kept, subscription load, cash cushion), one thing to try, and "not financial advice" on screen.

### Home
The Home hero (see section 4), pending bank messages ("Needs your input"), bills waiting to be split, **Today** (safe to spend per day from the overall budget, with a 7-day rhythm), accounts strip, goals strip, coming-up recurring items, budgets, an ask bar, recent transactions, and a plain privacy note ("Only you can see this").

### Goals
Savings goals with a target, optional deadline, contributions and withdrawals, ring progress and a suggested monthly set-aside.

### Settings and extras
Dark mode, language (English and Hindi, core strings), app lock, haptics, accent colours (Plus), **hide amounts** (the eye on Home masks every amount app-wide), **Help and feedback** (section 9), Share Kharchi, Export and backup, Privacy, Developer tools (demo data, bank-message simulator; kept visible so Play reviewers and the owner can see every screen).

## 4. Design

**"Ink & Marigold"**: a warm stone page, white cards, one deep ink surface for the number that matters, one marigold accent. Mirror of `src/theme/tokens.ts`; change both together.

| Role | Light | Dark |
|---|---|---|
| bg / surface | #F3F1EC / #FFFFFF | #0F0E12 / #1A1920 |
| text / muted / subtle | #16130E / #645D52 / #938B7E | #F4F2EE / #A8A298 / #7D776D |
| ink (buttons, selected chips, tab pill) | #1C1A22 | #F4F2EE (inverted) |
| hero card | #1C1A22 | #262431 (lifted charcoal, never a bright block) |
| primary (marigold, fills only) / link text | #F0A31B / #9A5A00 | #F5B33A / #F5B33A |
| income / expense | #1B7F57 / #B8402F | #5FD0A0 / #EE8A78 |

- Type: **Geist** 400/500/600/700; money uses tabular figures with the paise quieter, and big amounts shrink to fit. Radius 10/16/24/32/pill, gutter 20, minimum target 48dp.
- Marigold is for fills (add button, bars, dots), never body text. Green means income or "you are owed"; red means owing, over budget or negative; ordinary expenses stay ink.
- One icon language (line icons). Category, account and group emoji stay in the database and are drawn as line icons through `src/components/glyphs.ts`, so there is no migration. Icon tiles are a neutral plate with a single-colour glyph; colour is for meaning, not decoration.
- Floating tab capsule with a sliding ink pill; floating add button; ink toast pill; sheets with a strong ease-out (no bounce) and a plain-timer close; press scale 0.97. Everything collapses under reduce-motion.
- Principles: one primary action per screen; say what happened in human words; every list has a skeleton, an honest empty state and an error state with retry; colour is never the only signal; copy is plain and professional (no em dashes, no cute praise); new features must not need a permission, the network, analytics, payment code or a financial-advice claim.
- **The Home hero is the one deliberate port from the Fermor app.** The trend maths, reveal animation, tooltip and gesture code were copied into `src/lib/trend.ts` and `src/components/hero/TrendChart.tsx` along with Fermor's 37 tests (now run by Jest); `SpendHero.tsx` follows Fermor's `HomeHero` structure (label, time-frame pill and menu for 1 month, 3 months, 6 months and 1 year, hide-amounts eye, arrow to Insights, figure with quieter decimals, change line, interactive trend, five axis labels, Income and Kept footer) in Kharchi's colours with Kharchi's own data. Nothing else in Kharchi imitates Fermor and the two apps share no runtime code. An earlier trend line drew through an animated clip region and was invisible on a real phone; Fermor's polyline reveal fixed that.
- The app icon, splash and favicon are three centred rounded bars (ink and marigold, no letters, no ring, no currency symbol), a placeholder until the name is final.

## 5. Architecture

```
src/app/            Expo Router screens (tabs, modals, settings, group, friend, bills, goals, plus, review, feedback, voice, import-review ...)
src/components/     UI kit (ui.tsx, Icon, glyphs, charts, hero/TrendChart, FloatingTabBar, Sheet, Toast, PrivacyNote ...)
src/db/             Db interface, expo-sqlite adapter, migrations, backup/wipe (+ node:sqlite adapter for tests)
src/domain/         money (integer minor units, isValidMinor), types
src/features/       parser, pending, native, tracker (incl. frames, pulse, frequent, tags, exclude, receipts), groups, goals,
                    insights (health, review), ai (local engine, catalog), voice, capture, feedback, entitlements (plus, pricing),
                    bills, dev (seeders), sync and aggregator (no-op interfaces)
src/lib/            date, trend (ported), curve, haptics
src/theme/          tokens, ThemeProvider, motion
modules/kharchi-native/   Kotlin Expo module: SMS (Full), notification actions, widgets, bill camera and OCR, reminders
plugins/withKharchiNative.js   config plugin that wires the native module and strips forbidden components
docs/               index.html and privacy-policy.html (the public policy page), supabase-draft.sql (future backend, unused)
store/              Play listing copy (en, hi)
```
- No ORM: a thin repository layer over a small `Db` interface, so the same SQL runs on expo-sqlite in the app and on Node's `node:sqlite` in Jest (real-database tests, no native mocks).
- State: Zustand plus a tiny `useQuery` hook that re-runs on a global data-version bump. Charts are hand-rolled with `react-native-svg`.
- Every table carries `id, created_at, updated_at, deleted_at, dirty`; deletes are soft. Sync is designed in and switched off.
- **Migrations** (append only, never renumber a shipped one): 1 core, 2 groups, 3 bills (team), 4 goals, 5 feedback, 6 `transactions.excluded`.
- All amounts are validated (`isValidMinor`: positive whole paise up to ₹10,000 crore) and dates must be 1970 to about 2100.

## 6. Privacy, permissions and Play policy

> Engineering guidance, not legal advice. Google makes the final decision on every submission.

**Position.** The store build is local-first with the fewest sensitive permissions: no SMS permission, receiver or listener (so no SMS Permissions Declaration and no default-SMS-handler question), no INTERNET permission (`STORE_BUILD=1`), no bank integration, no Account Aggregator, no backend, no cloud AI, no analytics, no ads, no accounts. `allowBackup=false`. `npm run audit:manifest` inspects a built APK and fails on any forbidden permission, component, telemetry (including ML Kit's Data Transport) or target SDK below 36.

**Permissions in the final APK:** `POST_NOTIFICATIONS` (optional, user reminders), `USE_BIOMETRIC` (optional app lock), `VIBRATE`, `RECEIVE_BOOT_COMPLETED`. Explicitly absent and blocked: SMS, contacts, location, camera, microphone, storage, internet, network state, overlay, foreground service, push, install referrer.
- Camera: bill photos use the phone's own camera app through a private FileProvider, so Kharchi declares **no** CAMERA permission. Gallery uses the system photo picker (no storage permission). Receipts use the system file chooser.
- Voice uses the keyboard's dictation; `RECORD_AUDIO` stays blocked.
- Sharing uses the system share sheet; feedback opens the user's own mail app.

**Data safety form:** "Does your app collect or share any required user data types?" **No** (everything stays on the device, there is no internet permission and no third-party SDK that sends data). If Google's SDK flow asks about ML Kit, state on-device processing only. Re-check the form before adding sync, analytics, crash reporting, ads or billing.

**Other Play declarations:** privacy policy `https://gunanjr.github.io/kharchi/` (GitHub Pages from `/docs`, also linked in the app); ads No; app access: all functionality without login; target audience 18+; content rating Everyone; financial features: personal finance and expense tracking and bill splitting (no loans, banking, payments or investments); advertising ID No; target API 36; personal account is fine (new personal accounts need a closed test with 12 or more testers for 14 days); never misrepresent the publisher.

**Why paste and share do not trigger SMS policy:** Google restricts apps that request SMS or call-log permissions. Share and paste use the standard share sheet and clipboard: the user hands the app one message, the app holds no SMS permission, and nothing runs in the background.

**If you later add things, redo the privacy work first**
| Addition | What changes |
|---|---|
| Play Billing (Plus) | Adds `INTERNET` and `BILLING`; Data safety: purchase history handled by Google; privacy policy text; validate purchase tokens server-side without sending finance data |
| Crash reporting or analytics | New SDK means "collected" entries, disclosure, scrubbing of amounts and merchants |
| Cloud sync or remote AI | Full re-declaration; see `docs/supabase-draft.sql`; never sync raw messages |
| Re-enabling SMS (`production-full`) | Permissions Declaration Form (approval not guaranteed; mixed outcomes for expense apps); sideloaded APKs may show a Play Protect warning |

Drafting notes for the SMS declaration if ever pursued: core purpose is automatic personal expense tracking; bank alerts are parsed on-device, non-financial messages discarded instantly, nothing stored or transmitted; a prominent disclosure (`src/app/disclosure/[kind].tsx`) precedes the runtime dialog. Only pursue it after the privacy-first edition is live and users ask.

## 7. Plus, pricing and owner benefits

**Free forever:** adding and editing entries, unlimited groups and every split type, budgets, recurring, tags, search, CSV, standard insights, the tap-only assistant, say-an-expense, share-to-app, backup, app lock, dark mode, and **2 savings goals**.

**Plus** (a local preview switch; there is **no billing**): unlimited goals, every month of review history (free: this and last month), the money health score, sharing the review as an image, the receipt vault, accent colours. Rules live in `src/features/entitlements`; prices and the Free versus Plus table in `entitlements/pricing.ts`.

**Pricing (planning hypothesis):** ₹79 a month or ₹499 a year (47% saving yearly, about ₹41.58 a month). The Plus screen shows these, a side-by-side table and a **waitlist** button that records a choice on the phone; nothing is charged. A tester switch unlocks the features without payment.

**Why billing is not built:** Google Play Billing adds `INTERNET` and `BILLING`, a Data safety and policy update, a subscription disclosure, a refund policy, server-side token validation and licence-tester testing. That is a separate release. If billing cannot be tested properly, ship free and add Plus later.

**Economics (assumptions, replace with real numbers).** Recurring infrastructure cost of the financial product: ₹0. Lean monthly running cost about ₹1,000 to ₹15,500; early growth ₹15,000 to ₹65,500; one-off Play fee US$25. Net per annual subscriber at an illustrative 15% store fee is ₹424.15 a year. Break-even subscribers: about 142 for ₹5,000 a month, 283 for ₹10,000, 849 for ₹30,000, before acquisition spend. Verify Google's real fee. Growth: first 30 to 60 days organic plus at most ₹5,000 to ₹10,000 paid test; measure first-use completion, day-7 and day-30 retention, and paid conversion; use Play Console aggregate metrics, not an analytics SDK.

**Subscription plan when ready:** define real Plus features behind `Entitlements`; integrate Play Billing; validate tokens from a minimal service that sees only purchase tokens; handle restore, grace period, cancellation and refunds; update Data safety and the privacy policy before release.

**What the owner gets without any tracking:** conversion surfaces (Plus banner on More, locked previews on Insights, Goals and Receipts), organic growth (the review card says "Made with Kharchi"; Share Kharchi uses the system share sheet), support without a backend (in-app feedback to your email), and store assets for free (Load complete demo fills every screen for screenshots and for the Play reviewer). Measure with Play Console vitals, installs, ratings and the feedback inbox.

## 11. Bill scanning (team feature)

Snap a bill from the Scan bill widget, the shortcut or in the app; the app reads the items on the phone; later, when everyone is together, tap who had what. Tax, service charge, round-off and discounts are shared in proportion. The result is a normal itemised group expense, your share also lands in your tracker, and the photo is attached.

- **OCR:** Google ML Kit text recognition, bundled Latin model (works with no internet and no Play Services download). Rejected: unbundled model (downloads at runtime), cloud OCR or AI vision (uploads financial photos; a possible opt-in later), Tesseract (less accurate on thermal paper).
- **Photo:** the phone's own camera app into a private FileProvider (no CAMERA permission); gallery via the system photo picker; stored privately, auto-rotated, at most 2400 px.
- **Parsing (pure TypeScript, tested):** rebuild rows from boxes; parse from the right; skip totals and tax lines; find the payable total (Net or Grand over Total; ignore Sub total); **tax, discount and round-off = total minus sum of items**, never the printed GST lines (many Indian bills print GST as an included breakdown); repair OCR slips inside numbers; warnings tell the user to check.
- **Assigning:** person chips under each item plus Everyone; several chips share equally; a live "each person pays" preview; Save stays disabled until every item has an owner; names and prices are editable.
- **Money rules:** integer paise; largest-remainder rounding so shares sum exactly (property-tested on 200 random bills); negative extras (discounts) supported in the split engine.
- **Privacy:** only parsed fields (store, total, items, date) are stored; the raw OCR text is never saved; ML Kit's log-uploader components are removed from the manifest.
- **Limits:** quality depends on the photo; Latin script only; unusual layouts need edits; always check the total; scanning needs the installed app (in Expo Go use the sample bill or pasted text); verified on an Android 16 emulator with a synthetic receipt, so real-world accuracy needs a phone check.

## 12. Decisions log

1. Expo SDK 57 (the App Store Expo Go supports 57; the project had briefly drifted to 58). Routes live in `src/app/`.
2. No Drizzle: a thin repository layer over a `Db` interface, so SQL is tested against real SQLite.
3. Zustand plus a `useQuery` hook; no TanStack Query.
4. Hand-rolled SVG charts (works in Expo Go, fully themeable).
5. Money in integer minor units; `allocate()` uses largest remainder so shares always sum exactly.
6. Soft deletes and a `dirty` flag on every table for future sync.
7. The card-bill payment confirmation is rejected as `card_payment` so a card bill is not double counted as income.
8. Raw SMS handling: the receiver keeps the body in an app-private queue only until JS has parsed and acked it; the database keeps parsed fields and a hash; bodies are never logged.
9. Lint: React Compiler advisory rules are off because they flag intentional external-state sync patterns. `.npmrc legacy-peer-deps=true` for Expo SDK peer ranges.
10. Privacy-First is the production default; `STORE_BUILD=1` removes INTERNET and ACCESS_NETWORK_STATE; `expo-notifications` and several packages were removed because they pulled FCM, WAKE_LOCK and badge permissions; local reminders are a small Kotlin AlarmManager implementation (inexact alarms, re-armed after reboot).
11. Notification listener only with `EXPERIMENTAL=1`, never in Play builds.
12. No Play Billing or paywall in v1.0 (cannot be tested without a live account). `src/features/entitlements` is the hook.
13. The privacy policy is hosted from `docs/` via GitHub Pages and linked in the app. Developer tools stay visible in store builds so reviewers can exercise every screen.
14. The Quick add window is closed through a native `QuickAddRegistry`, and "opened externally" is signalled by `?src=ext` in the launch URL (two ReactActivities share one JS runtime).
15. The Quick Settings tile, the second launcher entry and all double-tap and back-tap features were removed (owner request); the experimental flag now adds only the notification listener.
16. Bill scanning uses on-device ML Kit; bill tax and discount are total minus items; a scan panel opened in-app goes straight to the split screen, opened from the widget it shows "Saved / Split now / Done".
17. UI redesign "Ink & Marigold" (section 4); emoji stay in the database and are drawn as line icons.
18. The Home hero is the one port from Fermor; nothing else imitates it.
19. Plus is a local switch with no billing (section 7).
20. Feedback leaves the phone only through the user's mail app (section 9).
21. Voice entry uses the keyboard's dictation and a deterministic parser; no microphone permission.
22. Entries can be left out of totals via `transactions.excluded`; balances still include them.
23. All amounts and dates are validated.
24. `expo-dev-client` is an optional dependency so `npx expo start` opens in Expo Go.

## 13. Publish to Google Play (step by step)

Do the steps in order; commands are typed in the Terminal inside the project folder.

**You need:** a Google account; a Play Developer account (US$25 once, ID check 1 to 3 days); an Expo account (free); the GitHub repo (hosts the privacy page); a support email (currently `bollugunwanth@gmail.com` in the policy); an Android phone; and, only for a personal account created after 13 Nov 2023, **12 testers** who stay opted in for 14 days. You do not need a website, a backend, a Google Cloud account or an SMS declaration.

**A. Name and app ID (first; permanent once uploaded).** Pick the name; search the Play Store and the trademark registers (India: tmrsearch.ipindia.gov.in) and the domain. Edit `src/config/app.json`: `appName`, `androidPackage` and `iosBundleId` (the same, e.g. `com.yourname.app`), `supportEmail`, `privacyPolicyUrl`. Run `npx expo prebuild --clean`.
**B. Privacy page.** Repo Settings, Pages, deploy from branch `main`, folder `/docs`. Wait for it, open `https://gunanjr.github.io/kharchi/`. If you changed the email, edit the bottom of `docs/index.html` and `docs/privacy-policy.html`.
**C. Expo.** `npx eas-cli login`, `npx eas-cli init` (prints a project ID), put `EAS_PROJECT_ID=...` in `.env`, then `npx eas-cli env:create --name EAS_PROJECT_ID --value ... --environment production --visibility plaintext`.
**D. Build.** `npm run build:store-aab` (accept "Generate a new Android Keystore" and back it up with `npx eas-cli credentials`). Test the exact same permissions first with `npm run build:store-test-apk`: add expense, paste a bank message, split a bill, scan a bill, backup and restore, dark mode. Optionally `npm run android:store` then `npm run audit:manifest` (expected: the four permissions above, target SDK 36).
**E. Play Console account.** play.google.com/console/signup, Personal or Organisation (needs D-U-N-S), pay, verify identity.
**F. Create the app and listing.** Free app, English (India). Paste the texts from `store/listing-en.md`; upload the 512 icon, the 1024x500 feature graphic and at least 2 (ideally 6 to 8) phone screenshots. To get screenshots: install the test APK, More, Developer, **Load complete demo**, screenshot Home, Insights, a group, the assistant, quick add, dark mode; afterwards use Delete all my data if you do not want demo data.
**G. App content forms.** Privacy policy URL; Ads No; App access; Content rating (Everyone); Target audience 18+; News, COVID, Government No; **Data safety: No data collected or shared**; Financial features: personal finance; Advertising ID No. There is no SMS form for this edition.
**H. Upload and go live.** Internal testing, create a release, upload the `.aab`, add yourself as a tester and install from Play. If the 12-tester rule applies: closed testing, 12 Gmail addresses, 14 days, then Apply for production. Production release, release notes, rollout; Google reviews in hours to days.
**I. Updates.** Raise `version` in `app.config.ts`, `npm run build:store-aab`, upload to Production.
**Before every release:** `npm run check`; the test APK installs and works; `npm run audit:manifest` passed; the privacy page opens; Data safety submitted. A device pass should cover onboarding, add expense, share a bank message, widgets, scanning a printed bill, backup and restore, dark mode, font scale 200% and TalkBack.
**Common problems:** "Package name already exists" (change `androidPackage`, prebuild, rebuild); EAS build fails (usually a missing `EAS_PROJECT_ID`); privacy link 404 (wait, or re-check Pages is `main` plus `/docs`); reviewer says login is needed (App access: all functionality without login; the demo tools show every screen); lost keystore (`npx eas-cli credentials` for a backup).
